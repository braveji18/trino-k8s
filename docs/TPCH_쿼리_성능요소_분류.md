# TPC-H 쿼리 성능 요소 분류

TPC-H 22개 쿼리(Q1~Q22)를 (1) 측정하는 성능 요소별로 분류하고, (2) 옵티마이저 평가 / 스토리지 엔진 처리량 / 병렬 처리 능력이라는 세 가지 평가 목적별로 핵심 서브셋을 정리한 문서입니다.

---

## 1부. 성능 요소별 분류

### 1. 테이블 스캔 / I/O 처리 성능
대용량 단일(또는 소수) 테이블을 전체 스캔하고 필터링하는 능력을 측정합니다.

- **Q1** – Pricing Summary Report: LINEITEM 전체 스캔 + 대량 집계 (스캔·집계 엔진의 기본 처리량 측정)
- **Q6** – Forecasting Revenue Change: 단일 테이블 범위 조건 스캔 (선택도/필터 처리)

### 2. 조인 성능 (특히 다중 조인 / 조인 순서 최적화)
여러 대형 테이블을 조인할 때 옵티마이저의 조인 순서 결정과 조인 알고리즘(해시/머지/네스티드 루프) 효율을 측정합니다.

- **Q2, Q5, Q7, Q8, Q9, Q10, Q11, Q21** – 5~6개 이상 테이블 조인이 핵심
- 특히 **Q8, Q9**는 조인 차수가 높아 조인 순서 최적화 능력을 강하게 테스트

### 3. 집계 성능 (GROUP BY / 집계 함수)
해시 집계 또는 정렬 집계 처리량과, 그룹 키 개수에 따른 효율을 측정합니다.

- **Q1** – 그룹 수는 적지만 입력이 매우 큼 (heavy group-by)
- **Q3, Q13, Q18, Q22** – 대량 그룹핑 및 중첩 집계

### 4. 서브쿼리 / 상관 서브쿼리 처리
서브쿼리 평탄화(flattening), 술어 내림(predicate push-down) 등 옵티마이저의 변환 능력을 측정합니다.

- **Q2, Q4, Q11, Q15, Q16, Q17, Q20, Q21, Q22**
- **Q17, Q20, Q21**은 상관 서브쿼리가 깊어 가장 까다로운 축

### 5. 정렬(ORDER BY) / Top-N 처리
- **Q3, Q10, Q18** – 정렬 후 상위 N건 추출 (정렬 비용 및 Top-N 최적화)

### 6. 표현식·조건 계산 처리
산술 연산, 문자열 매칭(LIKE), 복합 AND/OR 조건 평가 비용을 측정합니다.

- **Q6, Q19** – 복잡한 AND/OR 술어
- **Q8, Q12, Q14** – CASE 조건식 평가
- **Q9, Q13, Q16, Q22** – LIKE / 문자열 함수

### 요약 매핑 표

| 성능 요소 | 해당 쿼리 |
|---|---|
| 스캔/I·O | Q1, Q6 |
| 다중 조인·조인 순서 | Q2, Q5, Q7, Q8, Q9, Q10, Q11, Q21 |
| 집계(GROUP BY) | Q1, Q3, Q13, Q18, Q22 |
| 서브쿼리·상관 서브쿼리 | Q2, Q4, Q11, Q15, Q16, Q17, Q20, Q21, Q22 |
| 정렬·Top-N | Q3, Q10, Q18 |
| 표현식/조건 계산 | Q6, Q8, Q9, Q12, Q14, Q16, Q19, Q22 |

> 참고: 더 엄밀한 학술적 분류는 Boncz·Neumann·Erling의 논문 *"TPC-H Analyzed: Hidden Messages and Lessons Learned"*에서 제시한 **Choke Point(병목 지점)** 프레임워크가 표준으로 쓰입니다. 6개 대분류(집계 / 조인 / 데이터 접근 지역성 / 표현식 계산 / 상관 서브쿼리 / 병렬성)로 나누고 각 쿼리를 세부 병목에 매핑합니다.

---

## 2부. 평가 목적별 핵심 서브셋

쿼리들이 여러 요소에 걸쳐 있기 때문에, 각 목적에서 "가장 진단력이 높은 핵심 서브셋"과 "보조 서브셋"으로 나눠 제시합니다.

### 1. 옵티마이저 평가

플랜 선택의 품질(조인 순서 결정, 서브쿼리 변환, 카디널리티 추정, 술어 내림)을 측정합니다. 옵티마이저가 나쁜 플랜을 고르면 수십~수백 배 차이가 나는 쿼리들이 핵심입니다.

**핵심 서브셋**

| 쿼리 | 측정 포인트 |
|---|---|
| Q2 | 다중 조인 순서 + 상관 서브쿼리(min cost) 동시 |
| Q5 | 6테이블 조인 순서 결정 |
| Q7, Q8 | 고차 조인(7테이블 내외), 카디널리티 추정 민감 |
| Q9 | 큰 중간 결과를 만드는 조인 — 잘못 추정하면 폭발 |
| Q17 | 상관 서브쿼리(avg quantity) 평탄화 능력 |
| Q20 | 중첩 상관 서브쿼리 |
| Q21 | EXISTS/NOT EXISTS 세미·안티 조인, 가장 복잡 |

**보조 서브셋:** Q4(EXISTS 세미조인), Q11/Q15(서브쿼리·뷰), Q16(NOT IN 안티조인), Q22(NOT EXISTS)

> 옵티마이저 평가는 실행 시간보다 **EXPLAIN 플랜(조인 순서·조인 방식·서브쿼리 처리 방식)을 직접 비교**하는 것이 정확합니다. 특히 Q8, Q9, Q21에서 추정 행 수 vs 실제 행 수 괴리를 보면 추정기 품질이 드러납니다.

### 2. 스토리지 엔진 처리량

조인·옵티마이저 영향을 최소화하고, 순수 스캔 대역폭·압축 해제·컬럼 접근 효율을 측정합니다. 플랜이 단순해 거의 변하지 않는 쿼리가 이상적입니다.

**핵심 서브셋**

| 쿼리 | 측정 포인트 |
|---|---|
| Q1 | LINEITEM 전체 스캔 + 산술/집계 — 스캔 처리량의 표준 지표 |
| Q6 | 단일 테이블 범위 필터 스캔 — 가장 순수한 I/O·선택도 측정 |

**보조 서브셋:** Q12, Q14, Q19 — 대형 테이블 스캔 비중이 높지만 조인이 한두 개 섞여 순수도가 떨어짐

> Q1과 Q6은 조인 플랜 변동이 거의 없어 **하드웨어·스토리지·컬럼 압축의 순수 효과**를 분리해 보기 가장 좋습니다. 컬럼 스토어 vs 로우 스토어 비교, 압축 코덱 비교에 표준적으로 쓰입니다.

### 3. 병렬 처리 능력

큰 입력을 워커들에 분할해 처리하고(파티션 스캔, 병렬 해시 조인, 병렬 집계), 마지막에 결합하는 능력을 측정합니다. 입력·중간 결과가 크고 병렬화 이득이 큰 쿼리가 핵심입니다.

**핵심 서브셋**

| 쿼리 | 측정 포인트 |
|---|---|
| Q1 | 병렬 집계(parallel aggregation) 확장성 |
| Q9 | 대형 병렬 해시 조인 + 큰 중간 결과 분산 |
| Q13 | 대형 외부 조인 + 분포 집계 — 데이터 스큐 내성 |
| Q18 | 대량 GROUP BY + HAVING, 큰 입력 병렬 집계 |
| Q21 | 복잡한 병렬 조인의 워커 간 부하 분산 |

**보조 서브셋:** Q5, Q7, Q3 — 다중 조인이라 병렬화 이득은 있으나 옵티마이저 영향이 섞임

> 병렬 능력은 **스레드/워커 수를 1 → 2 → 4 → 8 …로 늘리며 같은 쿼리의 스피드업 곡선(scaling factor)**을 보는 방식이 정확합니다. Q13은 데이터 스큐가 있어 부하 분산이 나쁜 엔진에서 확장성이 무너지는 좋은 스트레스 테스트입니다.

### 한눈에 보기

| 목적 | 핵심 쿼리 | 측정 방식 권장 |
|---|---|---|
| 옵티마이저 | Q2, Q5, Q7, Q8, Q9, Q17, Q20, Q21 | EXPLAIN 플랜 + 추정/실제 행 수 비교 |
| 스토리지 처리량 | Q1, Q6 | 스캔 시간, 압축률·코덱별 비교 |
| 병렬 처리 | Q1, Q9, Q13, Q18, Q21 | 워커 수 대비 스피드업 곡선 |

> Q1과 Q21이 여러 목적에 겹치는 점이 흥미로운데, **Q1은 조인이 없어 옵티마이저 변수를 제거한 순수 처리량/병렬 지표**이고, **Q21은 가장 복잡한 플랜이라 옵티마이저와 병렬성을 동시에** 압박하는 쿼리이기 때문입니다.
